# 問題データの書き方

- 型は `src/types.ts` の `Problem`。1問1ファイルで作り、`src/data/problems/index.ts` の配列に追加する
- `segments` は問題文を前から順に分けたもの。着眼点にする部分だけ `fragmentId` を付ける
- `fragments` に着眼点の id と `priority`（見る順番の目安。1 が最初、重複なしの連番）を書く
- 1つの着眼点につき連想（`associations`）は1〜3個。`title` は思考ボードのカードに出すことばで、単語か短い文にする（例：「平方完成」「頂点か端点」。目安は20字まで。「〜 → 〜」のような説明の形にしない）。学習者がそのまま解答ボードに置けることばにする。`detail` はカードをタップすると開く説明で、「なぜそう考えるか・どう使うか」を書く。`combinations` の `title` と `detail` も同じ
- 連想には、あてはまる型の `patternId` を付ける（`src/data/patterns.ts`）。合う型がなければ型を追加する。型の `trigger`（何を見たら）と `idea`（何を連想するか）は、特定の問題の数値を含めず、別の問題でも通じる言い方にする。どの問題でも使われない型は残さない
- 連想・組み合わせには `graph` を付けられる（カードを開くと出る）。`expr` は LaTeX ではなく `x^2-2ax+3` のように書く。軸や区間が動く問題では `param` を付けて生徒が動かせるようにし、定義域があれば `domain` で太く描く。縦の範囲は、文字を端まで動かしても頂点や端点が見えるように `yMin` `yMax` を決める
- `combinations` の `from` は2つ。連想だけでなく、別の組み合わせの id も置ける。すべての組み合わせが連想から順にたどり着けること。くっつけた2つは新しい考えに代わるので、1つの考えを元にできる組み合わせは1つまで
- `skeleton` は模範の骨組み。設定で「配置を確かめる」を入れたときに、学習者の並べ方とくらべるのに使う（空でもよい）。使う順に上から並べ、段ごとに「そこで使う考え」を `thoughts` に書く（1つ目が基本。くっつける前の考えも認めるなら2つ目以降に足す）。各段の1つ目どうしは、一方が他方のもとになってはいけない（同時にボードに出せないため）
- `solution` の各行に、もとになった着眼点（`fromFragments`）と考え（`fromThoughts`）を必ず付ける
- 数式は `$...$` で囲む LaTeX。TypeScript の文字列なのでバックスラッシュは `\\` と書く
- 問題集の問題文をそのまま写さない（類題か自作にする）
- AIが作った問題データは、人が数学的な正しさを確認するまで完成扱いにしない
- 追加・変更後は `npm test` を実行する（参照切れ、LaTeX、到達可能性を検査する）
