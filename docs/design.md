# mathter 設計書

2026-11-11 時点

検討シート（`design-sheet.md`）と、試作を触ったうえでの意見をもとに、アプリ全体の設計をまとめたものです。検討シートで空欄・模索中だった項目には案を入れてあり、案であることを明記しています。

## 1. 目指すもの

### 一文で言うと

数学を学ぶ中高生が、問題文の語句や数式から「何を連想し、それをどう組み合わせて方針にするか」を身に付けるアプリ。

### 解決したい課題

模範解答には、考えた結果だけが書かれます。「問題文のどこを見て、何を思いついたから、その1行目が書けたのか」は書かれません。そのため、生徒は問題と解答を1対1で覚えることになり、授業は分かるのに初見の問題では手が止まります。

mathter は、この「解答に書かれない部分」だけを扱います。

### 使い終えた生徒ができること

- 初見の問題で、まず問題文のどこに目をつけるかを自分で決められる
- 目をつけた部分から、使えそうな考えを1つ以上思い出せる
- 完答はできなくても、方針を立てて途中まで進められる

### やらないこと（案）

検討シートで空欄だった項目です。ここを決めておくと、機能を足すときの判断がぶれません。

| やらないこと | 理由 |
| --- | --- |
| 答えを先に見せる、答えだけを教える | 解答を得る手段はすでに多い。AIチャットとの違いがなくなる |
| 答えの入力と採点、点数付け | 入力させて採点する仕組みは、連想を身に付ける体験と別物になる。確かめるのは解答ボードの配置だけ |
| 問題の自動出題、ドリル | くり返すかどうかは生徒が決める（検討シート4章） |
| 計算の途中式を1行ずつ教える | 計算の解説は教科書・参考書・動画で足りている |
| 求められていない表示 | 分かっていることを何度も見せられるわずらわしさを避ける（3章の原則2） |

## 2. 独自性

### 学習の単位を「問題」ではなく「連想」にする

ほかの教材は「問題」と「解答」を単位にしています。mathter は、次の対を単位にします。

> 着眼点（問題文の一部分） → 連想（そこから思いつくこと）

例：「最小値」→「2次関数なら、候補は頂点か端点」

この対は、1つの問題に閉じません。「最小値」という語は何十問にも出てきて、同じ連想が使えます。そこで、連想に**型**という共通の分類を付け、問題をまたいで扱えるようにします（5章）。これが mathter の中心です。型があることで、次のことができます。

- **生徒**：自分が集めた連想が「連想ノート」として貯まる。問題を解くほど増える自分の財産になり、初見の問題でも「この語は前に見た」と気づける
- **生徒**：1つの連想から、それを使うほかの問題へ飛べる。1対1の暗記ではなく、同じ考えが別の問題で使えることを体験できる
- **先生**：クラスがどの連想でつまずいているかを、問題単位ではなく考え方の単位で見られる
- **アプリ**：その生徒がすでに分かっている連想を知っているので、同じ説明をくり返さない

### いま使われているものとの違い

| 手段 | 得意なこと | 足りないこと | mathter が埋める部分 |
| --- | --- | --- | --- |
| 先生に質問 | その生徒に合わせて教えられる | 先生の力量と時間に左右される。全員には届かない | 先生の着眼点を問題データとして残し、全員がいつでも見られる |
| AIチャット | 解答をすぐ出せる | 「どこからどう考えるか」は聞かないと出ない。聞き方も必要 | 聞かなくても、着眼点と連想が問題文の上に用意されている |
| 解説動画 | 丁寧な説明 | 進む順番と速さが決まっている。分かる部分も飛ばしにくい | 見る場所も順番も生徒が選ぶ |
| 問題集の解説 | 正確な解答 | 思考の過程は書かれない | 解答の各行が、問題文のどこから生まれたかをたどれる |

## 3. 設計の原則

試作への意見から導いた原則です。機能を足すときは、この原則に合うかを先に確かめます。

1. **どこに目をつけるかも学習の対象**
   問題文には最初から色を付けません。色が付いていると、生徒は「どこを見るか」を考えずに済んでしまいます。
2. **求められたときだけ出す**
   見る順番は、ボタンを押したときだけ表示します。連想は、生徒がタップした部分のものだけ出します。決まった順に1つずつ見せる仕組みは作りません。理解が進んだ生徒ほど、アプリは静かになります。
3. **問題文を見て、思考して、解答を書く流れをそのまま画面にする**
   画面は「問題 → 思考ボード → 解答ボード」の順に並びます。問題文から拾った連想を思考ボードで組み合わせ、解答で使う考えを解答ボードに運び、使う順に上から並べます。アプリが扱うのは、この「解答の骨組みを作る」ところまでです。
4. **手で動かす**
   連想はボタンで送らず、ドラッグしてボードに置きます。カード同士を重ねるとくっつき、新しい考え1枚に代わります。考えを「集めて、合わせる」動作そのものを操作にします。
5. **解答は、たどるために見る**
   模範解答は生徒が開くまで見せません。開いたあとは、解答の1行をタップすると、もとになった問題文の部分とボードの考えが光ります。
6. **判定は、解答ボードの配置だけ。求められたときだけ**
   連想やくっつけ方に正解・不正解を付けません。合わない2枚を重ねても「新しい考えは生まれませんでした」と返すだけです。解答ボードでは、考えを正しい場所に置くことが求められるので、「配置を確かめる」を押したときに限り、場所が合っているかを返します。点数は付けません。
7. **1つの問題データが、すべての端末で使える**
   スマホ・PC・VRで画面や操作は変えますが、問題データと思考の仕組みは共通にします。

## 4. 学習体験

### 1問の流れ

| 手順 | 生徒がすること | アプリが返すこと |
| --- | --- | --- |
| 1. 読む | 問題文を読み、気になる部分をタップする | その部分に色が付き、連想が1〜3個出る（一言だけ） |
| 2. 集める | 使えそうな連想を思考ボードへドラッグする | ボードにカードが置かれる。「くわしく」で考える内容が開く |
| 3. 合わせる | ボードのカードを別のカードに重ねる | 合えば新しい考え1枚に代わる |
| 4. 並べる | 解答で使う考えを解答ボードへ運び、使う順に上から置く（例：平方完成は最初にするので1番上） | 「配置を確かめる」を押すと、場所が合っているかを段ごとに返す |
| 5. 解く | できた骨組みの順に、ノートで実際に解く（アプリの外） | 何もしない |
| 6. たどる | 模範解答を開き、行をタップする | その行のもとになった問題文の部分と、ボードの考えが光る |

手順1〜4の途中でやめて解き始めても、手順6だけ使っても構いません。順番を強制しないことが原則2です。

### ヒントの段階

検討シートで模索中だった項目です。一度に答えを見せないために、次の4段階に分けます。どの段階まで進むかは、すべて生徒の操作で決まります。

| 段階 | 分かること | 出し方 |
| --- | --- | --- |
| 0 | 何も出ない | 最初の状態 |
| 1 | 着眼点はどこか、どの順に見るか | 「見る順番を表示」ボタン。全部まとめて出て、もう一度押すと消える |
| 2 | その部分から何を連想するか（一言） | 問題文をタップ |
| 3 | なぜそう考えるか、どう使うか | カードの「くわしく」 |
| 4 | 連想をどう組み合わせるか | ボードでカードを重ねる |
| 5 | 考えを解答のどこで使うか | 解答ボードに置いて「配置を確かめる」 |

### 分かっていることをくり返さない仕組み

検討シートで模索中だった「ヒントを飛ばす仕組み」です。「もう分かる」の印を生徒の自己申告にすることは決定済みです。

- **基本は原則2**。求めないものは出ないので、分かっている生徒は段階2・3を使わずに進めます。
- **型ごとに「もう分かる」を記録する**。連想カードに「もう分かる」の印を付けられるようにします。印を付けた型の連想は、別の問題でも小さく表示し、「くわしく」を自動では開きません。
- **印は生徒の自己申告**。アプリが勝手に「理解した」と判断しません（原則6）。印はいつでも外せます。
- **記録は連想ノートに貯まる**。「見たことがある」「もう分かる」の2段階で、どの型を持っているかが一覧できます。

### くっつけるときの手がかり

合う相手を光らせると総当たりは減りますが、考える余地もなくなります。初期設定では手がかりを出さず、設定で「合う相手を光らせる」を選べるようにします（原則2）。

## 5. データの設計

### 3種類のデータ

| データ | 中身 | 誰が作るか | 置き場所 |
| --- | --- | --- | --- |
| 連想の型 | 「何を見たら → 何を連想するか」の共通の分類。単元ごとの辞書 | 運営（先生の確認つき） | アプリに内蔵。追加分はサーバー |
| 問題 | 問題文、着眼点、連想、組み合わせ、模範解答 | 先生、AI（人が確認） | 内蔵分はアプリ内。自作・配布分はサーバー |
| 学習記録 | ボードの状態、型ごとの「見た／分かる」、学習時間 | アプリが自動で記録 | まず端末内。サーバーには、認識番号・ニックネーム・学習時間を紐づけて置く |

### 連想の型（新しく追加するもの）

| 項目 | 例 |
| --- | --- |
| きっかけ | 「最小値」「最大値」（2次関数） |
| 連想 | 候補は頂点か、定義域の端点 |
| 考える内容 | 下に凸なら頂点が最も低い。頂点が定義域の外なら… |
| 単元 | 数学Ⅰ 2次関数 |

問題の中の連想は、その問題に合わせた言い回しを持ちつつ、どの型にあたるかを参照します。型に当てはまらない、その問題だけの連想があっても構いません。

### 問題（いまの試作からの拡張）

| 項目 | いまの試作 | 拡張 |
| --- | --- | --- |
| 着眼点 | 問題文の連続した一部分 | 離れた2か所を1つの着眼点にできるようにする（例：条件が問題文の前後に分かれている場合） |
| 見る順番 | 1つの順番 | そのまま |
| 連想 | 1つの着眼点に1〜3個 | 型への参照を追加 |
| 組み合わせ | 2枚 → 1枚。1本の道筋 | 別解に対応するため、複数の方針に分かれる形を許す |
| 解答の骨組み | 上から順の段。段ごとに、そこに置くと合っている考え | 別解ごとに持てるようにする |
| 模範解答 | 1つ。各行に、もとの着眼点と考えを対応づけ | 別解ごとに持てるようにする |
| 図 | なし | カードと解答に図（グラフ、図形）を付けられるようにする |
| 出どころ | なし | 作成者、確認者、確認日、もとにした教材（類題の場合） |

問題データは決まった形式（JSON）で保存し、形式に版番号を付けます。形式を変えても、古い問題が読めなくならないようにするためです。

### 自動検査

人が見落としやすいことは、機械で検査します（いまの試作にあるもの＋追加）。

- 着眼点・連想・組み合わせ・解答のあいだに、参照切れがない
- すべての組み合わせに、連想から順にたどり着ける
- 数式（LaTeX）がすべて表示できる
- 解答のすべての行に、もとになった着眼点と考えが付いている（追加）
- 連想のうち、どの解答の行にもつながらないものを知らせる（追加。わざと入れる「使わない連想」は許す）

## 7. 問題を増やす仕組み

学習アプリの価値は、問題データの量と質で決まります。検討シートで空欄だった「1問を作る手間」への案です。

### 作る流れ

1. 問題文を用意する（自作、または問題集の類題。そのまま写さない）
2. AIが下書きを作る（着眼点、見る順番、連想、組み合わせ、解答、型への対応）
3. 自動検査を通す（5章）
4. 先生が数学的な正しさと言葉づかいを確かめ、直す
5. 確認者と確認日を記録して公開する

### 手間の目安（案）

| 作り方 | 1問あたり | 備考 |
| --- | --- | --- |
| すべて手で作る | 30〜40分 | いまの試作の2問がこれにあたる |
| AIの下書き＋先生の確認 | 10〜15分を目標 | 段階2で実測し、届かなければ作成画面を直す |

最初の単元（数学Ⅰ 2次関数）で10問を作り、手間が現実的かを確かめてから範囲を広げます。

### 質の基準

- 連想の一言は、中高生がそのまま頭の中で言える長さにする
- 「くわしく」には、なぜそう考えるかを書く。計算の手順は書かない
- 見る順番には、先生が実際に読むときの順番を付ける
- AIが作ったものは、人が確認するまで公開しない

## 8. 画面の構成

| 画面 | 内容 | 段階 |
| --- | --- | --- |
| 学習画面 | 問題 → 思考ボード → 解答ボード（下に模範解答）。PCは横3列、スマホは縦3段 | 試作済み |
| 問題一覧 | 単元・難易度・型で絞り込む。取り組んだ問題に印 | 2 |
| 連想ノート | 集めた型の一覧と、型ごとの問題 | 2 |
| 問題を作る画面 | 先生用。AIの下書きを直す画面を兼ねる | 2 |
| 設定 | 文字の大きさ、くっつける手がかりの有無 | 2 |
| クラス | 配布した問題と、集計 | 3 |
| 学習時間・ランキング | | 4 |

VRでは、同じ問題データを使い、手元のノートを見ながら空間にボードを広げる別の画面を作ります（9章）。

## 9. システムの構成

### 段階ごとの構成

| 段階 | 構成 | 費用 |
| --- | --- | --- |
| いま〜段階2前半 | サーバーなしのウェブアプリ。問題は内蔵、記録は端末内。通信なしでも動くようにする（PWA） | 無料（GitHub Pages） |
| 段階2後半〜3 | サーバーを追加。AIによる下書き、問題の保存と配布、ログイン | AIの利用料とサーバー代がかかり始める |
| 段階5 | VR用のアプリを追加。問題データと思考の仕組みは共通 | ストアの登録料など |

### 分け方

- **思考の仕組み**（組み合わせ、ボードの状態、検査）は、画面から切り離して書く。いまの `src/thoughts.ts` がこれにあたり、VRでもそのまま使う
- **問題データ**は形式を決めて、アプリの外でも読めるようにする
- **AI**はサーバーを経由して呼ぶ。利用者の端末に鍵を置かない
- **内蔵の問題**は、通信がなくても使える

### 未定のまま残すもの

サーバーにどのサービスを使うか、VRをウェブ（WebXR）で作るかストア用アプリで作るかは、その段階に入るときに決めます。先に決めると、体験が技術のできることに引っ張られます。

## 10. 教育現場で採用されるための条件

| 条件 | 対応 |
| --- | --- |
| 学校の端末で動く | インストール不要のウェブアプリにする。学校で配られているタブレットやノートPCのブラウザで動かす |
| 個人情報を集めない | ここでいう個人情報は、本名や電話番号など本人を特定できる情報のこと。これらは集めない。サーバーに置くのは、アプリが発行する認識番号と、それに紐づくニックネーム・学習時間だけ。学習画面はログインなしで使える |
| 授業1コマに収まる | 起動してすぐ問題が開く。配布リンクから1回のタップで始められる |
| 先生の準備が軽い | AIの下書きで、1問10〜15分（7章） |
| 通信が不安定でも使える | 一度開いた問題は通信なしで使える |
| 読みやすい | 文字の大きさを変えられる。色だけに頼らず、印や枠でも区別する |
| 教科書に沿う | 問題を、学習指導要領の単元名で分類する |
| 効果を説明できる | 11章の指標で、導入前後の変化を示す |
| 続けて使える | 問題データを独自形式に閉じ込めず、書き出せるようにする。先生が作った問題は先生のもの |

学校で使う場合、各校・自治体の情報の取り扱いルールに合うかの確認が必要です。これは採用を打診する段階で、学校側と確かめます。

## 11. 成功指標と検証（案）

検討シート9章が空欄だったので、案を入れます。

| 見ること | 指標 | 確かめ方 |
| --- | --- | --- |
| 学習の成果 | 初見の問題で、着眼点を2つ以上挙げられる生徒の割合。方針を文章で書ける割合 | 使う前と後に、同じ形式の初見問題で比べる |
| わずらわしさ | 「分かっていることを何度も見せられた」と感じたか | 使ったあとの聞き取り |
| 使われ方 | 2回目以降も自分から開いた生徒の数。1問のうち、たどる（手順5）まで使った割合 | 端末内の記録 |
| 先生の手間 | 1問を作って配るまでの時間 | 実測 |
| 作り直しの基準 | 試した生徒の半数以上が「ノートで解くより手間が増えた」と答えたら、学習体験（4章）を見直す | 聞き取り |

## 12. 進め方

| 段階 | 作るもの | 確かめること |
| --- | --- | --- |
| 1. 試作（いま） | 学習画面と2問。公開済み | 先生と生徒数人に触ってもらい、中心となる体験がわずらわしくないか |
| 2. MVP | 連想の型と連想ノート、「もう分かる」の印、問題一覧、問題を作る画面、AIの下書き、通信なしでの利用。数学Ⅰ 2次関数で10問 | 11章の指標。1問を作る手間 |
| 3. 配布 | サーバー、配布リンク、クラスの集計、授業での投影 | 授業1コマで使えるか |
| 4. 拡張 | 解答の読み取り、学習時間と競い合い、単元の追加、有料化 | 続けて使われるか。問題を作る手間が回るか |
| 5. VR | VR用の画面。ノートの取り込み | VRのほうが良いと言えるか |

## 13. リスクと未決事項

### リスク

| リスク | 対応 |
| --- | --- |
| 問題を作る手間が回らない | 単元を絞る。AIの下書きの質を上げる。先生どうしの共有 |
| AIの下書きに数学的な誤りが入る | 人が確認するまで公開しない。自動検査を増やす |
| 連想を「覚える対象」にしてしまい、暗記が増えるだけになる | 型から別の問題へ飛べるようにし、同じ連想が違う問題で使えることを体験させる |
| 操作が増えて、ノートで解くより遅い | 手順を強制しない。使ったあとの聞き取りで確かめる |
| 学習時間の競い合いが、開いたままにするだけの時間を生む | 時間だけでなく、集めた型の数など別の指標も検討する |
| 類題が、もとの問題集に近すぎる | 数値と設定を変える。出どころを記録する |

### 決まったこと

| 項目 | 決定 |
| --- | --- |
| 「もう分かる」の印 | 生徒の自己申告にする |
| 最初の単元 | 数学Ⅰ 2次関数。10問 |
| 生徒の記録 | 認識番号・ニックネーム・学習時間を紐づけてサーバーに置く。本名や電話番号などの個人情報は扱わない |

### 決めていただきたいこと

1. **見る順番の中身**：いまの2問は私が付けた順番です。先生が実際に読む順番に直してください
2. **くっつける手がかり**：初期設定を「出さない」にする案でよいか
3. **料金の分け方**：内蔵の問題と学習画面は無料、AIの利用と学校向けの機能を有料にする案でよいか
4. **ニックネームの扱い**：生徒が自由に入力すると本名を入れる場合があります。自由入力にするか、用意した候補から選ばせるか
